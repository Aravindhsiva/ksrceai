1Introduction

What is a Large Language Model?

A large language model (LLM) is a neural network trained on huge amounts of text to do one very specific thing: predict the most plausible next chunk of text ("token"), given everything written so far. Everything an LLM can do — answering questions, writing code, holding a conversation, calling a tool — is that one skill, applied over and over, one token at a time.

It is not a database, a calculator, or a search engine

It doesn't "look things up" when you ask a question — it generates a statistically likely continuation based on patterns it saw during training. That's why it can sound completely confident about a wrong answer: fluency and correctness are two different things to a model whose only job is fluency.

A useful analogy — an LLM is closer to a very well-read improviser than a reference book. Give it a scene ("prompt") and it will continue it convincingly, drawing on everything it has absorbed. It will rarely say "I don't have this scene memorized" unless you explicitly build a system around it that rewards saying so — which is exactly what "structured output," "confidence gating," and "tool use" (later in this page, and both labs) are for.
2Possibilities

What this newly makes possible

On its own, an LLM is a very fluent but unreliable narrator. The interesting engineering starts when you combine it with code that adds structure, delegates the parts it's bad at, and decides when to trust it. Here's what that combination unlocks — each tagged with which lab demonstrates it.

📝 Text generation & rewriting

Draft, summarize, translate, or rephrase free-form text on demand.

🧩 Structured output

Force the model to answer in a fixed JSON shape instead of free prose — a contract your code can actually parse.

🛠️ Tool use / function calling

The model decides when to call a real function (a calculator, a lookup, an API) — the function does the actual work.

Budget Agent · Step 3

🎧 Multimodal input

Accept images, audio, or video alongside text in the same request — e.g. transcribing a spoken instruction.

📊 Self-reported confidence

Ask the model to rate its own certainty and list what's missing — data your code can branch on, instead of trusting tone.

🔁 Bounded agentic loops

Chain the above into observe → decide → act → recheck, with a hard iteration ceiling so it can never run forever.

…and what it's still genuinely bad at

Every lab in this course is designed around these limits, not in spite of them — the whole "agent" pattern is code compensating for exactly these failure modes.

🧮 Exact arithmetic cannot

It predicts plausible-looking numbers, it doesn't compute. Always delegate math to real code — never trust the model's own sum.

🎯 Being right by default cannot

Models are tuned to be agreeable and fluent. Confident-sounding output is not the same thing as correct output.

🕐 Knowing "right now" cannot

Its knowledge is frozen at training time. Without a tool feeding it live data, it will guess at anything that changes after that cutoff.

💸 Running for free cannot

"Free tier" means a rate-limited slice of real compute (on OpenRouter: 20 req/min, 50 req/day with no credits purchased) — not unlimited use.
