USER INPUT

Raw, messy request

No structure, no numbers guaranteed to be complete — just natural language.

"Can I afford a 3-day Goa trip on ₹8000 stipend, already spending ₹5000 on rent+food?"
STRUCTURED OUTPUT

Intent Parser Agent

Forces the model to return a fixed JSON shape — parseable by code, not free text.

{ "monthly_income": 8000, "fixed_monthly_costs": 5000, "destination": "Goa", "trip_duration_days": 3, "hard_constraints": [] }
TOOL USE

Cost Estimator

Any deterministic computation is delegated — never left to the model's own arithmetic.

TOOLestimate_trip_cost(destination, days)
TOOLcalculator(expression)
DETERMINISTIC — NOT MODEL JUDGMENT

Feasibility Check

A plain Python comparison: estimated_cost <= available_budget. Never trust the model to self-judge this.

✅ FEASIBLE

Return verdict

Straight through — no adjustments needed. Loop exits on iteration 1.

↻ NOT FEASIBLE

Constraint Solver Agent

Proposes one trade-off, applies it deterministically, then loops back to re-check feasibility.

⏱ bounded — max 4 iterations

What this teaches
LayerProduction meaning
Structured outputContract between the LLM and the rest of your codebase
Tool useDelegate anything deterministic — never trust the model's own arithmetic
Constraint loopReal agents solve for a goal under limits, with a bounded stop
Takeaway — an agent is a loop around an LLM, where the model makes judgment calls and your code enforces ground truth, structure, and stopping conditions.
